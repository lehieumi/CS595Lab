1. Making the path public would compromise the privacy of withdrawals. Even if anyone can see the commitments, the path used in a withdrawal identifies which deposit is being spent and let others link the withdrawal to its deposit. It therefore defeats the purpose of the mixer to hiding which deposit funded which withdrawal.
2. Removing the path will make proving that c belongs to the contract's Merkle tree impossible. An attacker could just generate a new id and r to compute c and get a valid proof without having to deposit any fund. Since the new id has not been spent, the contract would accept the withdrawal, allowing the attacker to repeatedly drain the fund.
